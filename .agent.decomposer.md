## RULES (STRICTLY FOLLOW THESE)

### Rule 1: NO VAGUE WORDS
❌ BAD: "Implement a robust backup system"
✅ GOOD: "Copy `index.json` to a new file named `index_backup_[timestamp].json`"

❌ BAD: "Handle edge cases gracefully"
✅ GOOD: "If the disk is full, stop and log error message: 'ERROR: Disk full at /path'"

### Rule 2: SHOW, DON'T TELL
❌ BAD: "Create a snapshot function"
✅ GOOD: "In `snapshot.rs`, write a function called `create_snapshot()` that does these 5 steps..."

### Rule 3: SPELL OUT EVERY STEP
Not "make a JSON file". Instead:
```
1. Open a text editor
2. Type exactly: {"id": "snapshot_2026-03-01", "created_at": 1234567890}
3. Save it as snapshot_metadata.json in /snapshots/ folder
4. If it fails, write error to stdout: "ERROR: Could not save snapshot metadata"
```

### Rule 4: ZERO INFERENCE
Don't assume the model knows:
- What `timestamp` format to use (specify: `2026-03-01_14-30-45`)
- How to handle errors (give exact error message text)
- What files to copy (list them by name)
- How many times to retry (specify number e.g., "try 3 times, then give up")

### Rule 5: CONCRETE SUCCESS CRITERIA
❌ BAD: "Make sure it works"
✅ GOOD:
  - [ ] Snapshot folder exists at `C:\snapshots\`
  - [ ] File `snapshot_2026-03-01_14-30-45\metadata.json` contains exactly: `{"id": "...", "created_at": ...}`
  - [ ] Running `cargo test snapshot_tests` passes all tests
  - [ ] Can restore a snapshot by running `restore_snapshot("2026-03-01_14-30-45")` and the files come back

### Rule 6: LIST EVERY FILE TO TOUCH
❌ BAD: "Update the database"
✅ GOOD: "Modify these files:
  - `src/snapshot.rs` ← add create_snapshot() function here
  - `src/commands.rs` ← add snapshot_command binding here
  - `src/main.rs` ← add this line at startup
  - `Cargo.toml` ← no changes needed"

### Rule 7: PROVIDE CODE TEMPLATES
Every task gets a stub. The model fills in blanks, not generates from zero.

Example:

❌ BAD: "Implement error handling in a production-grade way"

### Task 5: Implement auto-cleanup (keep only 30 snapshots or 7 days)

**File to Edit**: `src/snapshot.rs` (add to the file)

**Exactly What To Do**:

2. Query database: get ALL snapshots sorted by `created_at DESC`
3. Keep the NEWEST 30 snapshots
4. Also delete ANY snapshots older than 7 days
5. For each snapshot to delete: delete folder + database row
6. Log how many were deleted

**Code Stub To Fill In**:
```rust
pub fn cleanup_old_snapshots(db_path: &str, max_snapshots: i64, max_days: i64) -> Result<(), Box<dyn std::error::Error>> {
    let conn = Connection::open(db_path)?;
    let now = TODO_GET_CURRENT_UNIX_TIMESTAMP;
    let cutoff_time = now - (max_days * 86400); // 86400 seconds per day
    
    // STEP 1: Find snapshots to delete
    let mut stmt = conn.prepare("SELECT id, created_at FROM snapshots ORDER BY created_at DESC")?;
    let snapshots: Vec<(String, i64)> = stmt.query_map([], |row| {
        Ok((row.get::<_, String>(0)?, row.get::<_, i64>(1)?))
    })?
        .collect::<Result<Vec<_>, _>>()?;
    
    let mut to_delete = vec![];
    
    // Delete if: older than max_days OR beyond max 30 snapshots
    for (idx, (id, created_at)) in snapshots.iter().enumerate() {
        let should_delete = 
            *created_at < cutoff_time ||  // Older than 7 days
            idx >= max_snapshots as usize; // Beyond 30 most recent
        
        if should_delete {
            to_delete.push(id.clone());
        }
    }
    
    // STEP 2: Delete the folders and database rows
    for id in to_delete {
        let folder = format!("./snapshots/{}", id);
        fs::remove_dir_all(&folder)?; // Delete entire folder
        conn.execute("DELETE FROM snapshots WHERE id = ?1", rusqlite::params![&id])?;
    }
    
    Ok(())
}
```
